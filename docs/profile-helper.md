# 配置管理适配器协议

配置文件可能含订阅和节点凭据。本插件只显示宿主返回的配置名称与不透明 ID，不读取或保存配置正文。配置管理是可选功能：在插件设置中填写可信、不可被普通用户改写的 `profile_helper_path` 绝对路径后，面板才显示配置列表、切换和本地文件导入。插件以 Noctalia `runAsync(argv)` 调用 helper，不经过 shell。生命周期 helper 与配置 helper 是两个独立接口。

Mihomo 的 [`PUT /configs`](https://wiki.metacubex.one/en/api/) 能重载控制器配置，但路径受 Mihomo 工作目录及 `SAFE_PATHS` 约束；它不负责宿主的配置库、持久化选择和失败回退。因此插件不直接向该 API 发送配置正文或任意路径。宿主可以自行选择文件存储、API 重载或服务重启的实现，只要满足下列协议。

## 命令和结果

每次调用只传固定动词及至多一个参数：

```text
<profile-helper> list
<profile-helper> import <absolute-local-file>
<profile-helper> activate <profile-id>
```

`list` 的 stdout 是单个 JSON 对象，格式如下。`profiles` 最多 100 项；`id` 为 1–64 字节的 ASCII 字母、数字、点、下划线或连字符，首字符为字母或数字；`name` 是 1–80 字节、无控制字符的展示名称。ID 不应含路径语义。`active` 为列表中的 ID，或在没有已选配置时为空字符串。不得返回配置正文、订阅 URL、令牌或私有路径。

```json
{"profiles":[{"id":"sample-a","name":"Sample A"},{"id":"sample-b","name":"Sample B"}],"active":"sample-a"}
```

`import` 只接收本地绝对路径。它验证来源并把配置作为**新条目**加入受保护的配置库，不改变当前选择，也不重启正在运行的服务；成功时 stdout 输出 `{"id":"sample-b"}`。对于相同内容，宿主可返回已有条目的 ID，或创建新 ID，但不能静默覆盖当前可用条目。配置名称由宿主生成或在宿主侧清理后给出。面板使用可键盘操作的路径输入框；Noctalia 当前的声明式面板 API 提供 `ui.input`，此流程不依赖文件选择器。

`activate` 只接收最近一次 `list` 返回的 ID。成功时 stdout 输出 `{"id":"sample-b"}`，并保证该选择已持久化：若核心正在运行，新配置已通过健康检查；若核心已停止，保持停止状态，不因切换而自动启动。失败时 helper 应完成回退后才退出。插件随后重新执行 `list`，确认 `active` 是目标 ID 后才显示切换成功；导入也要在列表中确认新 ID。

退出码 `0` 表示成功。建议 `64` 表示参数无效，`65` 表示配置校验失败，`66` 表示来源不可读，`75` 表示启用失败且原配置已恢复，`76` 表示启用与回退都失败；其他非零码显示为通用失败。stderr 供宿主日志诊断，插件不展示它，避免泄露敏感内容。`list` 最长等待 8 秒，`import` 和 `activate` 最长等待 60 秒。超时后的实际结果可能不确定，用户应刷新列表并检查宿主状态；helper 必须能在中断或重试后恢复一致状态。

## 宿主实现顺序示例

以下是通用事务顺序，文件位置、验证命令、权限桥和服务操作由宿主决定：

1. `import`：限制来源为允许的本地文件，检查常规文件、符号链接、大小与权限；复制到私有临时文件，验证 YAML/Mihomo 配置和 controller 安全策略；以限制权限原子写入新的配置条目，返回新 ID。任何失败都不改当前选择。
2. `activate`：获取独占锁，记录旧 ID，再次校验目标条目；准备可原子替换的活动指针。若服务运行，切换后重载或重启并验证本机 API 与关键端口；失败则恢复旧指针、再次恢复服务并返回 `75`。回退也失败时返回 `76`，留下可诊断的事务记录。
3. `list`：在同一锁下读取配置库和活动指针，只输出上述非敏感 JSON。启动时处理上次中断的事务；不要把半完成的选择报告为成功。

例如，一个纯本地测试适配器可以先返回上面的 `list` JSON，对 `import /tmp/synthetic.yaml` 返回 `{"id":"sample-b"}`，再对 `activate sample-b` 返回 `{"id":"sample-b"}` 并使下次 `list` 的 `active` 为 `sample-b`。这只能验证插件与适配器的交互；部署适配器还必须实现前述校验、持久化和回退。

插件不支持 URL 或订阅导入。直接让通用插件下载 URL 会引入凭据保存、重定向、私网访问及来源验证问题；需要此能力时，应由宿主在自己的安全策略内取得并校验文件，再通过本地导入接口提供。不要给插件或 helper 泛化 sudo 权限；如果宿主需要高权限，应只授权这些固定操作和受保护的目标。
